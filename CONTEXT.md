# Catnap Context

Catnap is a vendor-neutral successor concept derived from Catnip. It describes an agent workspace manager whose long-term direction is not tied to one AI provider, code host, cloud runtime, or corporate sponsor.

## Language

**Catnap**:
Temporary codename for the Catnip-derived project while governance, naming, and ownership remain unresolved. Catnap is not a final brand.
_Avoid_: final product name, trademark commitment

**Catnip**:
The upstream W&B project that provides the current implementation lineage and product model for Catnap.
_Avoid_: Catnap, fork name

**Agent Workspace Manager**:
A development environment that gives coding agents isolated workspaces, terminal access, git-backed change tracking, previews, and remote control surfaces.
_Avoid_: Claude wrapper, Codespaces UI

**Vendor-Neutral Architecture**:
A design where AI providers, code hosts, cloud runtimes, identity providers, and edge networks are replaceable adapters rather than core assumptions.
_Avoid_: provider-agnostic as a slogan without explicit boundaries

**Fork Manifesto**:
A values document explaining why Catnap exists, what it inherits from Catnip, and what commitments guide future trade-offs.
_Avoid_: implementation plan, roadmap

## Example dialogue

Developer: "Are we renaming Catnip to Catnap?"
Domain expert: "No. Catnap is a temporary codename for a Catnip-derived successor concept. It lets us discuss direction without making a trademark or governance commitment."

Developer: "Is Catnap just a Claude Code manager?"
Domain expert: "No. Catnap is an Agent Workspace Manager. Claude Code can be one adapter, but the project should not depend on one agent provider."
