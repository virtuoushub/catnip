Architecture review · deepening opportunities

catnip — de-risking vendor coupling

Lens: turn three vendor dependencies into swappable adapters at deep seams, so the project outlives any one of them — Anthropic (Claude Code), GitHub/Microsoft (Codespaces), and the W&B→CoreWeave-hosted catnip.run (Cloudflare). Preference, not a hard rule: favour community-led / non-profit / FOSS adapter targets.

module seam leakage deep module

2026-05-28 · 4 candidates · derived from a 4-way parallel exploration of container/, src/, worker/, xcode/

Good news first — the rug-pull blast radius is small

Local catnip run does not phone home. container/internal/cmd/serve.go:162 only sets authRequired when CATNIP_PROXY is set; the SPA is embedded in the Go binary and assets ship inside it. If catnip.run vanished tomorrow, the core local product keeps working. What dies is the mobile + codespace-proxy convenience (iOS app + codespace wake/route). The deepening below is about making the vendor pieces optional by design, not rescuing a product that's already hostage.

Problem

Claude is currently coupled directly into the workspace lifecycle; adding Pi without a shared interface would fork the whole stack.

Solution

Wins

Problem

PR create/view/edit shell out to gh; remote parsing only matches github.com; GitHub's PR JSON shape leaks to callers.

Solution

GitHost interface (parse-remote, create-PR, list-repos, auth). GitHub adapter wraps gh; a Forgejo/Gitea adapter hits the HTTP API.

Wins

  • Clone / PR / repo-list speak one interface
  • Locality: host quirks in the adapter
  • FOSS targets: Forgejo/Codeberg, Gitea, GitLab CE
  • Existing git/operations.go already proves the pattern
Honesty check: today there's one host adapter (GitHub) → by "two adapters = a real seam," this is still hypothetical. The de-risking goal is what tips it to worth-exploring. Don't build it until a second host (e.g. Forgejo) is actually on the table — write the adapter and the seam together.

Problem

Durable Objects / R2 / Containers and the Hono c.env binding pattern leak Cloudflare into every route (~15×); the iOS app hardcodes https://catnip.run with no override.

Solution

HostedBackend interface over sessions / codespace-creds / keepalive / assets, mapped from env at createApp(). Add a baseURL override to iOS so a self-hosted backend works.

Wins

  • Swap Cloudflare for Postgres + S3-compatible (MinIO)
  • iOS / mobile can point at a self-host
  • Locality: binding access in one adapter
  • Local use already survives a rug-pull
Deletion test: removing catnip.run leaves local catnip run intact (serve.go:162) — only mobile + codespace-proxy break. So this seam buys optionality for the convenience tier, not survival of the core. Lower urgency than 1–2; highest payoff is the cheap iOS baseURL override + the codespace-store schema.

Top recommendation

Start with candidate 1 — the AgentRunner seam.

It's the candidate with the clearest strategic second adapter: Pi. The current Claude coupling should be extracted before Pi is added, so both agents share one workspace lifecycle instead of parallel stacks. Gemini/Google is explicitly not a roadmap target. This directly answers the stated #1 worry (Anthropic coupling), and it unblocks candidate 2 on the frontend. Highest leverage, lowest speculation. Candidate 3 waits for a real second git host; candidate 4 is optionality for the mobile tier, which the core product already lives without.
